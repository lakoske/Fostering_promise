# Fostering Promise — ТЗ на редизайн мобильной версии сайта (демо/промо-прототип)

## 1. Контекст и цель

Есть старый мокап мобильной версии сайта — платформа помощи с поиском и получением жилья
(`materials/FP_Screens_02.11@8x.png`), 8 экранов, синий корпоративный стиль.

Судя по функционалу (наставник/mentor, поэтапный чек-лист на жильё, хранилище документов,
обучающие материалы про кредитную историю и права арендатора, соц. услуги) — это платформа
поддержки людей, которым нужно сопровождение при выходе на самостоятельное жильё
(возможно, выпускники системы опеки — это предположение из названия проекта, скорректируйте,
если это не так).

**Цель этого этапа:** не production-продукт, а demo/promo-прототип —
кликабельный, визуально современный, на моковых данных, без реальной авторизации/бэкенда.
Нужен для питча/презентации и как основа для последующего анимационного ролика в After Effects.

**Задача:** сохранить структуру и логику мокапа, полностью переработать визуал,
при необходимости — точечно улучшить пользовательскую логику отдельных экранов.

## 2. Структура (берём из мокапа как есть)

8 экранов / состояний:

1. **Welcome / Login** — приветствие, аватар, "Welcome back, {Name}", CTA "Log in",
   баннер непрочитанных сообщений
2. **Dashboard (Home)** — шапка с аватаром и иконкой чата (badge), карточка
   "Housing Navigator" с прогресс-баром этапов, плитки быстрого доступа:
   Mentor Connect (badge), Housing 101 Info Portal, Your Digital Wallet, Resources
3. **Housing Navigator** — пошаговый чек-лист/визард (индикатор шагов), карточка
   задачи (например «Proof of Income» с пояснением, кнопка «I Have It», ссылка
   «How Do I Get It?»), навигация Back/Next
4. **Housing Repository** — список/грид вариантов жилья (фото, локация, кол-во юнитов),
   фильтр-теги (Housing, Credit), кнопка вызова фильтров
5. **Housing 101 Info Portal** — поиск, теги-категории, грид обучающих карточек
   с иконками (ваучеры, кредитная история, бюджет, права арендатора и т.д.)
6. **Your Digital Wallet** — описание раздела, список типов документов с иконками
   (свидетельство о рождении, водительские права, SSN и т.д.)
7. **Mentor Connect** — календарь (месяц, выделенные даты), карточка
   «Schedule time to meet» с предложенными датами
8. **Resources** — поиск, список городских/социальных сервисов с иконками
   (wellness, образовательные программы, работа, менторство)

**Общие элементы** (экраны 2–8): хедер с заголовком экрана, нижняя таб-навигация
(5 иконок — обучение, уведомления, профиль, настройки, меню).

## 3. Что пересматриваем в UX (предложения, не финал)

- Badge-уведомления и прогресс-бар Navigator — оставить, но сделать состояние понятнее
  (сейчас неочевидно, что означает точка на шкале «CO-SIGNER»)
- Housing Repository — по мокапу это просто карточки без явного шага «открыть детали
  объекта»; в демо можно добавить простой экран деталей объекта, если это усилит презентацию
- Единая паттерн-карточка (card) для Info Portal / Wallet / Resources — в оригинале
  три разных вида одного и того же по сути грида иконок+текста, можно унифицировать
  как переиспользуемый компонент
- Остальное — окончательно решаем по ходу вёрстки экрана, без лишнего заранее

## 4. Рамки этапа

**В работе:**
- Только мобильная версия (375–430px, резиновая мобильная адаптация)
- Все 8 экранов + переходы между ними (кликабельный прототип)
- Моковые данные (JSON в репозитории), без реального бэкенда/БД
- Без настоящей авторизации (кнопка Login — переход по прототипу, не проверка пароля)

**Вне рамок этапа (возможно, позже отдельно):**
- Десктопная версия/дизайн
- Реальный бэкенд, авторизация, хранение документов, интеграции
- Анимация в After Effects (следующий этап после сборки сайта)

## 5. Технологический стек

Уже развёрнуто в [`web/`](../web): **Next.js 15 + TypeScript + Tailwind CSS** (App Router).
Это разумный стек и для этого этапа — обоснование:

- **Next.js/React** — каждый экран = отдельный роут, между ними настоящая клиентская
  навигация; ощущается как реальное приложение, а не набор картинок
- **Tailwind** — быстро собрать чистую систему стилей (цвета, отступы, радиусы) под новый
  визуал без лишнего CSS
- **Framer Motion** (добавить) — переходы между экранами, микро-анимации карточек/прогресса.
  Два плюса: (1) продукт «оживает» уже на этапе демо, (2) реальные тайминги/easing переходов
  потом напрямую переносятся в AE — не придумываем анимацию дважды
- **lucide-react** (добавить) — набор современных иконок взамен исходных
- **next/font** — подключить один шрифт под новый визуал (что-то более дружелюбное/human,
  чем стандартный корпоративный sans — предложу варианты вместе с визуальным направлением)
- Картинки объектов/аватар — заглушки (Unsplash-подобные плейсхолдеры или сгенерированные),
  реальный контент клиент подставит позже

Бэкенд/БД/авторизация намеренно не добавляем — они не нужны для demo/promo и только
замедлят итерации. Архитектура (роуты, компоненты, моки как отдельный слой данных)
делается так, чтобы при необходимости позже безболезненно переключиться на реальный API.

## 6. Переход к анимации (After Effects) — подход

Рекомендуемый способ (гибридный), чтобы не строить UI дважды:

1. Сайт собирается с аккуратными переходами (Framer Motion) в реальном браузере
2. Экранная запись прохождения по сценарию в эмулированном мобильном вьюпорте
   (высокое разрешение/частота кадров)
3. Футаж уходит в AE: рамка устройства, титры, звук, доп. эффекты, финальный монтаж
   промо-ролика

Альтернатива — пересобрать экраны как векторные слои прямо в AE для полного
покадрового контроля, но это двойная работа над одним и тем же UI. Гибридный подход
предпочтителен, если не нужны эффекты, недостижимые в браузере (частицы, сложный 3D и т.п.).

## 7. Предлагаемый воркфлоу через Claude Code

1. **Согласование ТЗ** (этот документ) — вы читаете, поправляете, что не так
2. **Визуальное направление** — прежде чем верстать все 8 экранов, соберу 1 экран
   (Dashboard) в 2–3 вариантах стиля, смотрим в браузере через preview, выбираем
   направление — так не переделываем 8 экранов из-за неверного тона
3. **Дизайн-система** — цвета/шрифт/сетка/базовые компоненты (кнопка, карточка, тег,
   нижняя навигация, хедер) в Tailwind + React-компонентах
4. **Сборка экранов по одному** — каждый экран отдельным роутом на моках, после
   каждого — проверка в браузере (скриншот/интерактивно), правки сразу, не пачками в конце
5. **Связывание в кликабельный прототип** — нижняя навигация и переходы между
   экранами работают как в реальном приложении
6. **Деплой превью на Vercel** — присылаю вам ссылку, обкатываете на телефоне,
   собираем правки одним заходом
7. **Финальная полировка** — микро-анимации, состояния загрузки/пустых списков
8. **Передача в анимацию** — по завершении сайта решаем: экранная запись + AE,
   или другой вариант из п.6, и переходим к самому ролику

Работаем по экрану за раз с проверкой в браузере на каждом шаге — это и есть
основной цикл через Claude Code для такой задачи: короткая итерация,
визуальная проверка, следующий шаг.
